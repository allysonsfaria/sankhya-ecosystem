# Projetos

A tela de **Projetos** permite aos usuários visualizar, criar, editar e gerenciar projetos cadastrados na plataforma, assim como o fluxo de trabalho que deseja seguir. Ela centraliza em um único local todas as informações relacionadas aos projetos ativos, facilitando o gerenciamento e a organização das atividades.

## 1 - Tela inicial

![Imagem 1: 1 - Tela inicial](https://ajuda.sankhya.com.br/hc/article_attachments/42639406835095)

### Componentes da tela

#### Barra de pesquisa

- Campo de busca para localizar projetos cadastrados pelo nome.
- Ícone de lupa para execução da pesquisa.

#### Botões de ação

- **Criar Projeto:** Botão verde, localizado no canto superior direito.

#### Tabela de projetos

| Campo | Descrição |
| --- | --- |
| **Nome** | Nome do projeto. Exemplo: `PROD` |
| **Chave** | Identificador único do projeto. Exemplo: `PROD` |
| **Status** | Toggle de ativação/desativação do projeto. Quando ativado, aparece com ícone verde. |
| **Responsável** | Nome e ícone do usuário responsável pelo projeto. Exemplo: `Valdson` |
| **Pessoas** | Ícones representando os usuários participantes do projeto. |
| **Ações** | Ícone de lápis que permite a edição do projeto. |

#### Paginação

- Controle para número de linhas por página.
- Indicação da página atual e total de registros.

---

### Funcionalidades

- **Criar Projeto:** Permite adicionar um novo projeto ao sistema.
- **Editar Projeto:** Através do ícone de lápis na coluna “Ações”.
- **Ativar/Inativar Projeto:** Utilização do botão toggle para controlar o status.
- **Pesquisar Projeto:** Facilita encontrar projetos específicos por nome.
- **Gerenciar Participantes:** Visualização rápida de quem está envolvido em cada projeto.

---

### Comportamentos esperados

- A lista de projetos é carregada automaticamente ao acessar a tela.
- A alteração do status de um projeto (ativo/inativo) é imediata.
- A edição de um projeto leva o usuário para uma nova tela ou modal com informações detalhadas do projeto.

## 2 - Criando um projeto

### Etapa 1 – Informações

![Imagem 2: Etapa 1 – Informações](https://ajuda.sankhya.com.br/hc/article_attachments/42639381299863)

#### Objetivo:

Capturar os dados essenciais para a criação e identificação do projeto dentro da plataforma.

#### Campos do Formulário:

| Campo | Obrigatório | Descrição |
| --- | --- | --- |
| **Nome do Projeto** | Sim | Nome identificador do projeto. Será exibido na listagem principal de projetos. |
| **Chave de Referência** | Sim | Código ou sigla única para representar o projeto, por exemplo, `NEPPO`, `PROD`, etc. |
| **Líder** | Sim | Usuário que atuará como líder do projeto. Deve ser selecionado a partir de uma lista de usuários disponíveis. |
| **Responsável** | Sim | Pessoa responsável direta pela gestão e andamento do projeto. Também selecionado via dropdown. |

#### Comportamentos:

- Os campos obrigatórios impedem o avanço para a próxima etapa caso não sejam preenchidos.
- A interface é amigável, com mensagens de ajuda como “Dê um nome ao projeto” e “Ex: NEPPO”.
- Ao clicar em **Próximo**, o sistema salva os dados informados e direciona o usuário à etapa “Pessoas”.

#### Botões de ação:

- **Cancelar:** Encerra o processo de criação sem salvar alterações.
- **Próximo:** Avança para a Etapa 2 – Pessoas.

---

### Etapa 2 – Pessoas

![Imagem 3: Etapa 2 – Pessoas](https://ajuda.sankhya.com.br/hc/article_attachments/42639381462039)

### Objetivo:

Permitir a inclusão de colaboradores no projeto, garantindo que os membros certos tenham visibilidade e acesso às funcionalidades relacionadas.

### Elementos da tela

#### Campo de pesquisa

- **Label:** "Adicione os colaboradores ao projeto"
- **Placeholder:** “Pesquisar grupo ou pessoa”
- Campo que permite buscar e selecionar usuários ou grupos de usuários previamente cadastrados no sistema.

#### Botão de ação

- **Botão verde – “Add Grupo Ou Pessoa”**

  - Adiciona novos participantes ao projeto.
  - Abre uma nova linha para pesquisa e seleção.

#### Ícone de lixeira

- Permite remover um grupo ou pessoa da lista antes da finalização da criação do projeto.

### Comportamentos

- O campo de busca sugere automaticamente nomes de usuários ou grupos à medida que o texto é digitado.
- É possível adicionar múltiplos usuários e grupos ao projeto.
- Ao remover um participante, o sistema atualiza a lista instantaneamente.
- Essa etapa não bloqueia o avanço caso não haja colaboradores adicionados (dependendo da configuração da plataforma).

### Botões de navegação

| Botão | Ação |
| --- | --- |
| **Voltar** | Retorna à Etapa 1 – Informações |
| **Próximo** | Avança para a Etapa 3 – Fluxo de Trabalho |
| **Cancelar** | Encerra o processo de criação sem salvar as alterações |

### Etapa 3 – Fluxo de trabalho (workflow)

![Imagem 4: Etapa 3 – Fluxo de trabalho (workflow)](https://ajuda.sankhya.com.br/hc/article_attachments/42639381634967)

### Objetivo:

Definir a jornada de execução das atividades dentro do projeto, configurando os status e transições que refletem o andamento das tarefas.

### Elementos da tela

#### Mapa de fluxo

- Representação visual do processo com **estágios conectados por transições**.
- Fluxo padrão exibido:

  - **Começar → Para Fazer → Em Progresso → Concluído**

#### Status

| Tipo de Status | Cor | Descrição |
| --- | --- | --- |
| **Pendente** (Para Fazer) | Laranja | Indica tarefas ainda não iniciadas. |
| **Em Andamento** (Em Progresso) | Azul | Representa tarefas em execução. |
| **Concluído** (Concluído) | Verde | Marca tarefas finalizadas. |

#### Painel lateral de elementos

- **Status pendente:** permite adicionar novos status de início.

  - [GIF animado: Imagem 5: Status pendente: permite adicionar novos status de início.](https://ajuda.sankhya.com.br/hc/article_attachments/42639378268055)
- **Status andamento:** adiciona status intermediárias de ação.

  - [GIF animado: Imagem 6: Status andamento: adiciona status intermediárias de ação.](https://ajuda.sankhya.com.br/hc/article_attachments/42639366118551)
- **Status concluído:** define status de encerramento de tarefas.

  - [GIF animado: Imagem 7: Status concluído: define status de encerramento de tarefas.](https://ajuda.sankhya.com.br/hc/article_attachments/42639366410391)
- **Transição:** conecta os status, determinando o fluxo permitido.

  - [GIF animado: Imagem 8: Transição: conecta os status, determinando o fluxo permitido.](https://ajuda.sankhya.com.br/hc/article_attachments/42639412685847)
- **Regras:** (opcional, se ativado) permite definir validações ou restrições de movimentação.

  - ![Imagem 9: Regras: (opcional, se ativado) permite definir validações ou restrições de movimentação.](https://ajuda.sankhya.com.br/hc/article_attachments/42639408759703)

#### 1. Restringir quem pode mover um item

Permite definir quais usuários estão autorizados a executar uma transição específica entre status.

- **Exemplo de uso:** Apenas o Daniel pode mover um item de “Em Progresso” para “Concluído”.
- **Campos:**

  - **Para transição:** Seleciona a transição específica (ex: “Em Progresso → Concluído”).
  - **Permitir essas pessoas:** Busca e seleciona usuários autorizados a realizar essa transição.
- **Botões:**

  - `Adicionar regra` – Salva a configuração.
  - `Cancelar` ou `Voltar` – Interrompe a criação da regra.

#### 2. Atribuir um item

- Automatiza a atribuição do item a um usuário específico após a movimentação do item em uma transição definida.
- **Exemplo de uso:** Após mover uma atividade para “Em Progresso”, o item é automaticamente atribuído ao responsável técnico.
- **Campos:**

  - **Para transição:** Define qual transição acionará a regra (ex: “Para Fazer → Em Progresso”).
  - **Permitir essas pessoas:** Define para quem o item será atribuído automaticamente.
- **Botões:**

  - `Adicionar regra` – Aplica e salva a regra no fluxo.
  - `Cancelar` ou `Voltar` – Cancela a configuração.

### Funcionalidades

- É possível adicionar, remover ou reordenar status.
- Transições podem ser redesenhadas conforme a lógica desejada.
- O zoom e ajuste de tela são controlados pelos ícones no canto inferior direito.
- O fluxo “Começar” é o ponto inicial fixo e obrigatório.
- As transições devem respeitar uma lógica de continuidade.

### Botões de navegação

| Botão | Ação |
| --- | --- |
| **Voltar** | Retorna à Etapa 2 – Pessoas |
| **Próximo** | Avança para a Etapa 4 – Notificação |
| **Cancelar** | Encerra o processo de criação sem salvar |

### Etapa 4 – Notificação

[GIF animado: Imagem 10: Etapa 4 – Notificação](https://ajuda.sankhya.com.br/hc/article_attachments/42639413108503)

### Objetivo:

Configurar quais perfis receberão notificações automáticas com base em eventos específicos ocorridos durante o ciclo de vida de tickets e atividades do projeto.

---

### Elementos da tela

A tela exibe uma tabela com os seguintes campos:

| Campo | Descrição |
| --- | --- |
| **Evento** | Ação ocorrida no sistema que pode disparar uma notificação. Ex: “Um item foi movido”, “Você foi atribuído a um item” |
| **Destinatário** | Perfis que receberão a notificação: Administrador, Agente, Supervisor e Usuário |
| **Ações** | Ícone de lápis que permite editar os destinatários de cada evento |

---

### Eventos disponíveis para configuração

- Uma entrada do registro de trabalho foi excluída
- Uma entrada do registro de trabalho foi editada
- O trabalho foi registrado
- Um comentário foi editado
- Alguém fez um comentário
- Um item foi movido
- Um item foi excluído
- Você foi atribuído a um item
- Um ticket foi editado

Todos os eventos podem ser ativados ou desativados individualmente por meio de botões do tipo toggle.

Novos eventos serão incluídos de acordo com a evolução da solução.

---

### Edição de notificações

Ao clicar no ícone de edição (lápis), abre-se um modal com:

- **Evento selecionado** (exibido no topo)
- **Destinatários disponíveis** com caixas de seleção:

  - Administrador
  - Agente
  - Supervisor
  - **Usuário** (com observação especial abaixo)

Atenção: Embora a opção “Usuário” esteja visível e selecionável, as notificações para o cliente final (Usuário) ainda não estão funcionando neste momento. Essa funcionalidade está prevista para uma próxima versão da plataforma. Recomenda-se não depender dessa entrega para processos críticos até a correção ou ativação oficial.
