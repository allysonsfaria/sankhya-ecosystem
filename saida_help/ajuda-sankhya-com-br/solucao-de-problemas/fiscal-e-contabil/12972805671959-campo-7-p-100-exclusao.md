# Campo 7 P-100 Exclusão

**(1)** O campo 7 do registro P100 é construído por dois "valores", o primeiro será tratado como **"EXCLUSAO BRUTA ATIVIDADE"** e o segundo **"ABATIMENTO BRUTO ATIVIDADE"** e, por meio de três consultas na base de dados, que são realizadas para a construção do próprio registro P100, o sistema calcula o referido campo:

![Imagem 1: Primeiramente é feita uma Consulta nos livros fiscais ICMS/IPI, filtrando por documentos com origem:](https://ajuda.sankhya.com.br/hc/article_attachments/17268875997719) Primeiramente é feita uma Consulta nos livros fiscais ICMS/IPI, filtrando por documentos com origem:

- Complemento;
- Devolução;
- Estoque;
- E o código do modelo de documento deve estar entre: (7, 8, 9, 10, 11, 26, 27, 57, 67);

**(1)** Veja nessa consulta como os dois valores serão calculados, e que juntos vão compor o total das 'exclusões':

![Imagem 2: Primeiro valor, denominado EXCLUSAO BRUTA ATIVIDADE , é calculado da seguinte forma:](https://ajuda.sankhya.com.br/hc/article_attachments/17268875997719) Primeiro valor, denominado **EXCLUSAO BRUTA ATIVIDADE**, é calculado da seguinte forma:

- A primeira validação feita é se o produto está com o campo **"Enquadrado no Reintegra/Prev.?"** ativado, se não estiver, o sistema não irá calcular valor algum para o produto/nota no que compõe o total do campo de EXCLUSÕES.
- Obedecida a regra anterior, o sistema compara se o código do País que está vinculado ao Estado e, consequentemente à cidade do parceiro ligado ao documento nos livros, é 55 (Brasil), que deve ser igual ao valor informado no parâmetro **CODPAISBRASIL.** Se os valores forem iguais, então o sistema faz mais uma validação, no cadastro do CFOP, se o campo "Receita bruta p/EFD Contribuições" está marcado como "soma". Então, nesse ponto o sistema vai pegar no livro o valor do IPI e somar com valor de ST, aumentando assim os valores que serão apresentados como EXCLUSÕES. Mas, se no cadastro do CFOP, o campo citado não estiver somando, o sistema vai somar os dois campos de IPI e ST nos livros, porém com o efeito de diminuir os valores que serão apresentados como EXCLUSÕES.
- Se a regra do código do país não bater com o parâmetro CODPAISBRASIL o sistema vai analisar se no cadastro de CFOP está com a marcação **"Receita bruta p/EFD Contribuições"** como **"soma"** e, estando, o sistema vai construir os valores de exclusões com o valor contábil do produto na nota. Mas se o CFOP não estiver com a devida marcação de soma, o sistema vai usar o valor contábil do item para diminuir o valor que será calculado no campo 7 do P100, ou seja, terá o efeito de diminuir o total desse campo.

![Imagem 3: Segundo valor, denominado ABATIMENTO BRUTO ATIVIDADE , é calculado da seguinte forma:](https://ajuda.sankhya.com.br/hc/article_attachments/17268875999127) Segundo valor, denominado **ABATIMENTO BRUTO ATIVIDADE**, é calculado da seguinte forma:

- A primeira validação feita é se o produto está com o campo Enquadrado no Reintegra/Prev.? ativado, se não estiver, o sistema não irá calcular valor algum, para o produto/nota no que compõe o total do campo 7 de EXCLUSÕES.
- Obedecida a regra anterior, o sistema analisa se no cadastro do CFOP se o campo Receita bruta p/EFD Contribuições está marcado como "soma", se estiver, nenhum valor será acrescentado como EXCLUSÃO. Porém, se estiver como subtrai, o sistema vai pegar como valor de exclusão o valor contábil do item, nos livros fiscais.

![Imagem 4: Na segunda consulta que o sistema realiza é feito uma Consulta nos livros fiscais de ISS, filtrando por documentos com…](https://ajuda.sankhya.com.br/hc/article_attachments/17268876002071) Na segunda consulta que o sistema realiza é feito uma Consulta nos livros fiscais de ISS, filtrando por documentos com origem:

- Estoque;
- E o item usando na nota, deve ser um 'serviço';
- Nessa consulta, o sistema não alimenta valores denominados como **"ABATIMENTO BRUTO ATIVIDADE"**, apenas os valores denominados **EXCLUSAO BRUTA ATIVIDADE**, da seguinte forma:
- A primeira validação feita é se o produto está com o campo Enquadrado no Reintegra/Prev.? ativado e se o código do país do parceiro ligado ao documento não é igual ao valor do parâmetro CODPAISBRASIL. Se for essas as condições das configurações, o sistema vai pegar o valor contábil nos livros de ISS e somar ao total das 'exclusões', mas se essas duas condições não forem atendidas, não será calculado valor algum.

![Imagem 5: Na terceira consulta, o sistema busca nos livros de ICMS/IPI, os lançamentos que tem como origem:](https://ajuda.sankhya.com.br/hc/article_attachments/17268876003095) Na terceira consulta, o sistema busca nos livros de ICMS/IPI, os lançamentos que tem como origem:

- Redução Z;
- E o item que foi gerado no livro não pode ser um 'serviço' e não pode estar em seu cadastro, com o campo 'usado como' igual a:
- Revenda (por fórmula);
- Matéria prima;
- Nessa consulta, o sistema não alimenta valores denominados como **"EXCLUSAO BRUTA ATIVIDADE"** apenas os valores denominados **"ABATIMENTO BRUTO ATIVIDADE"** e é feito da seguinte forma:
  - A primeira validação feita é se o produto está com o campo Enquadrado no Reintegra/Prev.? ativado, se não estiver, o sistema não irá calcular valor algum, mas se estiver marcado, o sistema passa para uma próxima validação, que se trata do cadastro do CFOP. Se o campo Receita bruta p/EFD Contribuições está marcado como "soma", o sistema **não** vai apropriar valor algum para esse tipo de documento, mas se o cadastro do CFOP estiver como 'subtrai', será levado o valor do seguinte cálculo:
    - VALOR TOTAL ITEM NA NOTA - VALOR DE DESCONTO DO ITEM NA NOTA.
