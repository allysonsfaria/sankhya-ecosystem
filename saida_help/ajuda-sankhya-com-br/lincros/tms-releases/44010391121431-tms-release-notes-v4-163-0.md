# [TMS] - Release Notes - v4.163.0

![Imagem 1](https://ajuda.sankhya.com.br/hc/article_attachments/44010340092183)

A versão 4.163.0 traz avanços na adequação fiscal e tributária, evolução das integrações ERP ↔ TMS e maior controle de visibilidade por unidade nos endpoints de integração, além de melhorias no fluxo de Notas Fiscais de Serviço.

No módulo Geral, destaque para o suporte à DUIMP (Declaração Única de Importação), com aceitação de números alfanuméricos no campo de declaração de importação e adaptação de filtros, listagens e processamento de CT-e. Também foi disponibilizada nova funcionalidade na edição da NFS-e que permite vincular Notas Fiscais de Serviço a Notas Fiscais de Venda de forma prática, com filtros avançados e personalização persistida por usuário, além da possibilidade de adicionar múltiplas NFs simultaneamente via colagem de chaves, com validação automática.

Em APIs e Integrações, foram disponibilizados novos endpoints para criação e cancelamento de NFS-e via integração ERP ↔ TMS, com suporte a XML/PDF em Base64, dados de impostos e protocolo único de rastreabilidade. Também foram criados parâmetros de empresa que permitem filtrar os documentos retornados pelos endpoints de integração conforme as unidades vinculadas ao usuário webservice, abrangendo ocorrências, embarques, cargas fracionadas e MDF-es.

Em Cotação e Auditoria de Fretes, foi corrigida a base de cálculo do IBS e CBS quando o ISS é por dentro, passando a ser calculados sobre o valor líquido do frete.

De forma geral, a 4.163.0 é uma versão focada em adequação fiscal, ampliação das integrações via API e maior governança sobre a visibilidade de dados por unidade.

## Descrição

Ajuste no endpoint de integração /ocorrencia/buscarRegistrosParaIntegracao para permitir filtragem dos documentos com base nas unidades vinculadas ao usuário webservice.

## O que mudou/O que há de novo?

- Foi criado um novo parâmetro de empresa: filtrarUnidadesOcorrenciaIntegracao. Quando ativado (true), esse parâmetro faz com que o endpoint retorne apenas as ocorrências das unidades vinculadas ao usuário webservice autenticado. Por padrão (false), o sistema mantém o comportamento atual, retornando todas as ocorrências disponíveis da empresa. Quando o usuário não tem nenhuma unidade selecionada no cadastro (todas do lado “Disponíveis”), o endpoint retorna todas as ocorrências da empresa (comportamento alinhado com o padrão estabelecido no card #14771 para CT-e e Fatura).

Módulo: Geral

## Descrição

Disponibilizados endpoints de integração ERP ↔ TMS para manipulação de Notas Fiscais de Serviço (NFS-e).

## O que mudou/O que há de novo?

## POST /api/notaServico/criar

- Permite criar NFS-e a partir de integração ERP, com ou sem vínculo com NF-es de venda.
- Quando `notasFiscais` não for informado, a NFS-e é criada com coluna **Importação = ERRO** e mensagem informativa.
- Quando `notasFiscais` tiver dados incompletos, NF-e não encontrada ou já vinculada, a NFS-e é criada com **Importação = ERRO** e mensagem descrevendo o problema.
- O campo `tipoPreConhecimento` foi removido da requisição. O sistema assume **NORMAL (1)** internamente.
- Suporta envio de arquivo XML/PDF em Base64 e dados de impostos (ISS, IBS, CBS).
- Retorna status e protocolo único de rastreabilidade em todos os cenários.

## POST /api/notaServico/cancelar

- Permite cancelar NFS-e existente informando número, CNPJ e motivo de cancelamento (entre 15 e 255 caracteres).
- O campo `serie` é opcional.
- Retorna status **CANCELADO** e protocolo único em caso de sucesso.
